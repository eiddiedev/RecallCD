你现在接手的是 `B-SIDE` 项目。请先阅读当前代码再动手，重点文件是：

## 项目背景

比赛赛道已经调整为「内容重构：让视频成为你的生活搭子」。现在不再需要遵守互动空间 8MB 包体限制，也不再以纯离线 Demo 为唯一约束，但当前项目仍然是一个可本地运行的轻量前端原型。

我们的产品方向不是音乐学习工具，而是面向泛人群的「音乐视频资产分类 + 私人 FM」：

> B-SIDE 把用户收藏的音乐视频资产整理成一张张 CD，并通过 AI 风格的收藏习惯分析，生成私人音乐视频 FM，让视频成为用户的情绪陪伴、回看入口和内容搭子。

## 当前分工

请只做「FM 电台模块」相关工作。

我的 partner 会负责当前主页面的音乐类型分类，也就是现有 CD 展示架、CD 数据分类、当前页面视觉与分类逻辑。不要大改这些部分。

你负责右上角 FM 按钮之后的模块。当前页面已经有一个右上角 FM 收音机按钮：

```js
window.addEventListener("bside:fm-open", (event) => {
  console.log(event.detail.selectedCollection);
});
```

点击按钮时会派发 `bside:fm-open` 事件，`detail.selectedCollection` 是当前选中的 CD/分类 id。请基于这个事件打开你的 FM 模块。

## 需要实现的目标

实现一个「私人音乐视频 FM」面板或全屏层，作为独立模块接在当前页面上。

核心体验：

1. 用户点击右上角 FM 按钮。
2. 页面打开一个 B-SIDE FM 界面。
3. FM 界面用“AI 已分析你的收藏习惯”的方式，展示若干个私人电台。
4. 用户可以切换电台，看到推荐的音乐视频资产卡片。
5. 推荐不要表现为播放 copyrighted music，也不要跳外链；推荐的是“音乐视频内容方向 / 收藏资产 / 电台人格”。

## 推荐内容模型

可以使用内置 mock 数据，不需要真正接大模型，也不需要真的解析用户收藏。重点是把概念演出来。

示例数据结构：

```js

      memory: "副歌前那一下贝斯进入很有画面感。",
      tags: ["City Pop", "Live", "雨夜"]
    }
  ]
}
```

## UI 要求

- 保持现有暗色、CD、黑胶、电台质感。
- FM 界面可以是覆盖层，不要跳页面，不要破坏当前 3D CD 架。
- 右上角或顶部要有关闭按钮，返回原来的 CD 架。
- 可以做几个电台 tab，例如：
  - `雨夜 FM`
  - `通勤 FM`
  - `现场 FM`
  - `复古 FM`
- 每个电台展示：
  - 电台名
  - AI 分析依据
  - 适合场景
  - 3-5 张推荐音乐视频资产卡片
- 每张卡片展示：
  - 标题
  - 类型：LIVE / COVER / MV / REVIEW / PLAYLIST
  - 推荐理由
  - 记忆点
  - 标签

## 交互要求

- 点击 FM 按钮打开。
- 点击关闭返回。
- 电台之间可点击切换。
- 推荐卡片可以横向滑动或纵向滚动，优先保证移动端好用。
- 可以加一个轻量按钮，例如 `重新蒸馏`，点击后切换一组 mock 推荐或播放一个短暂 loading 动效。
- 不要把交互做复杂，不要引入重型状态管理。

## 技术要求

- 当前项目是原生 HTML/CSS/JS + Three.js，不要迁移到 React/Next。
- 尽量新增独立模块，例如 `js/fm.js`，并在 `index.html` 里引用。
- 不要大改 `js/main.js`，除非只是为了更好地暴露数据或事件。
- 不要重构 CD 展示架、黑胶轮播、分类逻辑。
- 不要删除 partner 可能要继续改的分类相关代码。
- 如果需要样式，可以先写在 `index.html`，但请集中命名为 `fm-*`，避免污染现有样式。
- 所有新增资源走相对路径。

## 不要做的事

- 不要实现真实音乐播放。
- 不要外链到歌曲或音乐平台。
- 不要接真实 AI API。
- 不要改成音乐学习/练习工具。
- 不要做复杂登录、上传、云端收藏。
- 不要推翻当前首页的 CD 架交互。
