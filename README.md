# B-SIDE

**B-SIDE** 是一个面向泛音乐用户的音乐视频资产重构工具：它把用户平时刷到、收藏的音乐类视频，重新整理成可浏览、可理解、可播放、可继续推荐的私人音乐档案。

我们希望解决的不是“专业音乐学习者如何练习”，而是一个更普遍的内容消费场景：很多人每天都会收藏音乐现场、翻唱、混剪、舞蹈、歌曲推荐或氛围感视频，但这些内容通常停留在收藏夹里，难以再次被理解和使用。B-SIDE 试图把这些碎片内容转化成一个像私人唱片架和私人 FM 一样的体验。

## 项目定位

赛道：**抖音精选 - 内容重构：让视频成为你的生活搭子**

核心问题：

> 音乐视频内容能否被转化为用户看得懂、用得上，并且愿意反复打开的个人能力？

B-SIDE 的答案是：把音乐视频从“刷过/收藏过”重构为三层资产：

1. **可浏览的资产**：用 CD 架和 CD 盒模型承载不同音乐类型的视频集合。
2. **可理解的资产**：通过音乐类型分类、视频标签、互动数据和 AI 摘要说明“为什么推荐给你”。
3. **可行动的资产**：进入 B-SIDE FM 后，用户可以获得一组基于收藏习惯生成的私人歌单推荐。

## 核心功能

### 1. 音乐视频 CD 架

首页是一个可交互的 3D CD 架。每个 CD 代表一个音乐类型或内容集合，例如：

- Jazz
- Hip-Hop
- R&B
- Electronic
- Folk
- Cinematic

用户可以滑动浏览 CD，点击后进入该类型的视频集合。这个设计把“普通列表”变成了更有记忆点的音乐资产库，也呼应了音乐内容本身的实体媒介感。

### 2. CD 详情页与视频浏览

进入 CD 后，用户可以看到该集合中的音乐视频内容：

- 视频封面预览
- 作者、标题、标签、音乐名
- 点赞、评论、收藏等内容反馈信息
- 黑胶唱片式弧形轮播浏览
- 本地视频预览播放

这部分的目标不是做传统播放器，而是让用户像翻唱片、翻收藏一样重新消费自己的音乐视频资产。

### 3. 音乐类型分类

项目包含一个音乐类型分类服务 `classify_server.py`。

实现方式：

- 使用 FastAPI 提供 `/api/classify` 接口。
- 支持上传音频或视频文件。
- 视频会先通过 ffmpeg 抽取音频。
- 使用 Hugging Face 上的 `dima806/music_genres_classification` 音频分类模型。
- 将 GTZAN 的 10 类音乐结果映射到产品内的 6 类音乐资产：
  - jazz
  - hiphop
  - rnb
  - electronic
  - folk
  - cinematic

这样用户导入音乐视频后，系统可以把它归入对应 CD 集合中。

### 4. B-SIDE FM 私人推荐

右上角 FM 按钮进入 B-SIDE FM。

FM 模块会基于用户在 CD 架中的浏览和收藏行为，生成私人音乐视频歌单。它不是简单地随机推荐，而是把用户的内容偏好转化成：

- 推荐歌单
- 推荐理由
- 场景说明
- 记忆点描述
- 可播放/可跳转的音乐视频卡片

AI 在这里参与的是“内容理解与重组”：它把用户收藏习惯变成更易理解的推荐解释，让用户知道自己为什么会喜欢这一组内容。

### 5. 本地视频与外链播放

当前版本以本地 demo 视频为主，视频文件放置在：

```text
assets/videos/
```

封面资源放置在：

```text
assets/covers/
```

由于完整视频文件体积较大，线上版本更适合采用“对象存储 + 前端引用 URL”的方式；当前比赛展示版本优先保证本地体验和产品闭环。

| 评审维度 | B-SIDE 的对应设计 |
| --- | --- |
| 场景与问题洞察 | 选择“音乐视频收藏”这一高频内容场景。目标用户不是专业音乐人，而是所有会听歌、收藏音乐内容的普通用户。 |
| AI 能力与产品结合 | AI 不只是生成文案，而是参与音乐内容理解、分类、偏好总结和私人歌单重组。 |

| 创新性与延展潜力 | 用实体唱片/CD 的交互隐喻重构短视频收藏夹，未来可扩展到旅行、美食、健身、课程等其他内容资产。 |

## 技术实现

### 前端

- HTML / CSS / JavaScript
- Three.js 本地文件渲染 3D CD 盒
- Canvas 生成视频封面与 CD 贴图
- 本地视频预览播放
- 黑胶唱片式弧形轮播浏览
- `localStorage` 记录部分用户行为

### AI 与分类

- `classify_server.py`：音乐类型分类后端
- `js/fm.js`：B-SIDE FM 推荐模块
- 可接入 DeepSeek API 生成推荐歌单与推荐理由
- API Key 不应写入公开仓库，正式部署时应放入环境变量或服务端代理

### 资源组织

```text
.
├── index.html              # 主入口
├── js/
│   ├── main.js             # CD 架、详情页、视频浏览主逻辑
│   ├── fm.js               # B-SIDE FM 推荐逻辑
│   ├── classifier.js       # 分类辅助逻辑
│   └── three.module.min.js # 本地 Three.js
├── assets/
│   ├── covers/             # 视频封面
│   └── videos/             # 本地 demo 视频
├── images/                 # UI 背景与图标
├── classify_server.py      # 音乐类型分类服务
└── classify.html           # 分类服务测试页
```

## 本地运行

### 启动主项目

推荐用任意静态服务器打开：

```bash
python3 -m http.server 4173
```

然后访问：

```text
http://127.0.0.1:4173/index.html
```

### 启动音乐分类服务

安装依赖：

```bash
pip install -r requirements.txt
```

启动服务：

```bash
python classify_server.py
```

分类接口：

```text
POST http://127.0.0.1:5050/api/classify
```

也可以打开：

```text
http://127.0.0.1:4173/classify.html
```

上传音频或视频进行分类测试。

## 展示说明

当前版本围绕评审体验准备了一组音乐视频样例，用于完整呈现“内容收藏 - 类型归档 - 视频回看 - 私人 FM 推荐”的核心闭环。评委可以直接从 CD 架进入不同音乐类型，查看视频内容如何被重新组织，并体验 B-SIDE FM 如何把收藏习惯转化为更容易理解和再次使用的歌单推荐。

在产品设定上，B-SIDE 尊重音乐内容的版权边界：完整作品可以通过合法平台外链继续收听或观看，项目本身重点展示内容理解、资产重组和推荐交互能力。未来接入真实线上服务后，视频资产、用户收藏和 AI 推荐可以进一步扩展为云端个人音乐内容库。

## 一句话总结

B-SIDE 不是另一个播放器，而是一个把音乐视频收藏变成私人音乐资产和私人 FM 的内容重构体验。
